# Assamese Manual-Collection Sources

Source-level tracking (one line per site/document-collection). Per-document
detail (pages, word counts, timestamps) lives in `COLLECTION_LOG.md`.

**Directory layout note:** `raw/{ocr,scrape}/` holds unfiltered extracted text
(OCR-corrected or wikitext-stripped, but no purity filtering); `clean/{ocr,scrape}/`
holds the same content after the line/word purity filter and ৰ/ৱ language-ID
heuristic (course requires both retained, not just clean). This split was
added after OCR/wikipedia were already fully processed with clean-only
output -- their pre-fix runs were relabeled into `clean/` rather than
reconstructed (`raw/ocr/` stays empty until a new book triggers OCR again),
except Wikipedia, which was cheap to fully rerun locally and now has a
genuine raw+clean pair for all 25,110 articles.

- **`../../docs/assamese/books/` (SCERT/NCERT Assamese-medium textbooks, Class IX-X, 29 PDFs)** — OCR complete. 4627/4627 pages processed, 100% via Tesseract `ben` fallback (0 pages had a usable Unicode text layer -- confirmed real body text, not a watermark, just non-Unicode legacy glyph fonts / scanned images throughout). Pre-raw/clean-split output (clean-only) lives in `clean/ocr/<slug>.txt` per book; `raw/ocr/` is empty (see directory layout note above).
- **niyomiyabarta.com** — Assamese news site. Scraping concurrently via `scripts/scraper.py` (sitemap-driven discovery, `<article>` extraction, line+word-level purity filter, ৰ/ৱ language-ID heuristic). 8,843 articles scraped total (~2.37M clean words), ~41,159 remaining. Five post-fix batches so far (two ended via external kill mid-batch rather than the cap, both confirmed checkpoint-safe -- no data lost, just no graceful BATCH-STOP log line): `raw/scrape/niyomiyabarta.txt` ~1.77M words (unfiltered, dual-write since the raw/clean fix), `clean/scrape/niyomiyabarta.txt` ~2.39M words (includes pre-fix history + post-fix batches). Batched: 2000 articles or 1hr per run, holding for go-ahead between batches.
- **asomiyapratidin.in** — Assamese news site. Sitemap-driven (`news-sitemap.xml`), `<article>` selector. 137 scraped pre-fix (`clean/scrape/asomiyapratidin.txt`), fully drained for its current sitemap window (0 new on last run) -- dual raw+clean writes apply once new articles appear.
- **as.wikipedia.org** — Assamese Wikipedia. **Course clarification reversed the live-API-only guidance: dump-based collection counts as manual too, since we do our own preprocessing.** `scripts/wiki_dump_extract.py`: downloads `aswiki-latest-pages-articles.xml.bz2` (~67.5MiB, dumps.wikimedia.org), streams it (never fully decompressed to disk), strips wikitext markup to prose by hand (regex-based: templates/tables handled via iterative innermost-removal for nesting, no external wikitext-parser dependency), then runs the same purity filters as OCR/scrape output. **Complete, with full raw+clean pair (re-ran after the raw/clean fix since it's ~1 minute of pure local processing, effectively free): 25,110 articles, `raw/scrape/as_wikipedia.txt` ~10.79M words (unfiltered), `clean/scrape/as_wikipedia.txt` ~10.30M words (purity-filtered), 0 suspect-language pages excluded** (matches expectation for native-written content).

- **xobdo.org** — First online Assamese dictionary (est. 2006), wiki-based/community-edited (Wikipedia-equivalent manual-collection logic: live-scraped with our own preprocessing, not a bulk dump). `scripts/xobdo_scrape.py`: the `/alpha` page bakes all 361 alphabetical range pairs into its HTML (`loadWordRange(start, end, langId=2, ...)`), each mapping directly to a clean JSON API (`/2025-web/api/wordsalpha.php`) returning word + part-of-speech + full definition text -- no HTML parsing needed. **Complete: 47,972 dictionary entries, `raw/scrape/xobdo.txt` ~523K words (unfiltered), `clean/scrape/xobdo.txt` ~476K words (purity-filtered), 0 suspect-language ranges excluded.** Modest volume as expected for a dictionary (vs. Wikipedia-scale), clean and unambiguously native. Ran in ~14 min (361 ranges, throttled). Note: candidate `assamesedictionary.org` (claims 293K+ definitions) was not pursued -- lower-confidence/less independently verifiable than xobdo per the lead we had; xobdo's own Wikipedia page independently corroborates it.

**3-source concurrency feasibility check (requested by user, before the dump-based pivot):** ~16 min of real concurrent runtime (niyomiyabarta + asomiyapratidin + live-API wikipedia) measured combined throughput at ~840K words/hour vs. the earlier single-source baseline of ~130K words/hour -- roughly a 6.5x gain from running sources concurrently, confirming concurrency is worth scaling further. niyomiyabarta and asomiyapratidin continue running concurrently now that wikipedia is dump-based (no longer part of the live thread pool). Awaiting go-ahead before expanding toward the ~10-source target.
